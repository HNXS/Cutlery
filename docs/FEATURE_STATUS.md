# Feature status — 0.5.0 alpha

The original 187 rows remain the design scope, not a claim of completion. “Implemented (alpha)” means a present code path, not production qualification. Partial rows list their actual boundary. Acceptance criteria in `features.json` remain the original future gates.

| ID | Feature | Alpha status | Current boundary |
|---|---|---|---|
| F001 | Create, open, recent projects and settings | Implemented (alpha) | Create/open/save and presets; Project → Open recent lists the last 10 projects opened or saved (kept in the data folder; missing ones are marked and dropped when chosen). Started without a project, Cutlery shows a start screen: six canvas formats (16:9 Full HD and 4K, 9:16, 4:5, 1:1, 720p), the recent projects, Open and Recover autosave. Project → Preferences… sets the format and frame rate of new projects, how long still images last, how many earlier versions are kept per project (0–100) and whether the start screen shows; they are saved in the data folder (settings.json) and invalid values are refused. |
| F002 | Media bin, folders, collections and search | Implemented (alpha) | The library tab shows all media, or only videos, audio or images, or one folder; a search box narrows it by name (every word must match, any order and case). Folders are created, renamed and deleted (their media stays) in the library; media is moved by right-click, new imports go into the folder on show, and folders are saved with the project. Unused media can be removed from the library. Titles, graphics and sounds moved to a separate Add tab so the list has room. No nested folders or saved smart collections. |
| F003 | Drag/drop and background media analysis | Implemented (alpha) | Library-to-track and local file drops, async probing and waveform analysis, partial-error reporting. Dropped or imported folders are searched with the folders inside them for media files (by extension, up to 500 per import), added in path order into a library folder named after the dropped folder (on a track: one after another). The import shows how many files are left and can be stopped; the file being read and those waiting are skipped. |
| F004 | Nondestructive media references | Implemented (alpha) | Relative project references; originals never edited. |
| F005 | Missing-media relink and replace | Implemented (alpha) | Validated relinking of one source (same media type, probed again). When media is missing, the library offers "Find in a folder…": every missing file is looked up by name (any case) in that folder and the folders inside it (up to 50000 files) and relinked in one undo step; among several files of the same name, the one in the most similar folders wins. Files found by name are not probed again, so a different file of the same name is not detected. |
| F006 | Collect Project and portable media bundle | Implemented (alpha) | Project → "Collect project and media…" copies every media file, LUT and font added in Cutlery that the project uses into an empty folder (media/, luts/, fonts/ with clashing names numbered) and saves <folder>.cutlery there with relative paths, in the background with progress. Opening a project loads the fonts beside it. Refuses projects with missing media; no trimming of unused source ranges. |
| F007 | Project schema migrations | Implemented (alpha) | Reads schema 1/2 without moving clips; writes schema 3 with stable track IDs and snapping/magnetic modes. Older versions cannot read new saves. |
| F008 | Atomic save, autosave and rolling backup | Implemented (alpha) | Atomic save and one recovery file; each save keeps the previous project file as a version in the data folder (the newest 20 per project), and Project → Restore an earlier version… puts one back after keeping the current file as a version too. Backups are whole project files; media is not copied. |
| F009 | Undo/redo and deep edit history | Partial | Whole-project undo snapshots, 60 by default and 10–500 in Preferences. Each save also keeps the undo and redo steps (up to 100) in the data folder (history/, the 50 most recently saved projects); opening the same file unchanged brings them back, so undo goes on across sessions. A file changed elsewhere starts without history. No history browser. |
| F010 | Crash and corrupted-cache recovery | Partial | Recovery snapshot; waveform cache files that fail validation and thumbnail strips that cannot be read are made again; work folders left by a crash are removed at the next start (see F164); nested renders missing from the cache are rendered again. A lock file in the data folder marks a running session; one left by another process means the last session did not end normally, and the start page says so (with "Recover autosave" and the log). Warnings and the errors shown to the user are logged with their time in the data folder (logs/cutlery.log, the previous megabyte kept as cutlery.1.log; Help → "Open the log folder"). No crash dumps or automatic reports. |
| F011 | Multiple open projects and project versions | Planned | Not implemented in this alpha. |
| F012 | Local search index for metadata and dialogue | Partial | The media library search matches every word against a medium's name, file name, folder, kind, picture size (e.g. 1920x1080), usage rights and credit, and what is said in it: transcripts already made for captions or "Edit by text" (any language, read from the AI cache and kept in memory per file). Media found by speech show the words around the first match with its time. No persistent index file; media never transcribed are not searched by speech. |

| F014 | Person search with user labels | Planned | Not implemented in this alpha. |
| F015 | Local templates and replaceable media slots | Partial | Project → "Save as template…" keeps the whole project (also from inside a nested sequence) under a name in the data folder; Project → "New from template" and the start screen start a new, unsaved project from it, which stays out of the recent list; templates can be removed. Any medium can be swapped for another file of the same kind (library right-click → "Replace with another file…"), keeping its clips' trims. Templates refer to their media where it is (not copied); no marked placeholder slots. |
| F016 | Local brand styles and reusable assets | Partial | Text styles for every project (data folder, styles.json, up to 200): "Save…" in the text inspector keeps a title's font, size, colours and gradient, bold/italic, alignment, spacing, outline, shadow, box, highlight colour and build-up animation under a name (the same name replaces it); "Apply a style…" sets them on all selected titles in one undo step; styles can be removed. What the format cannot carry (titles and graphics, effects, colour, keyframes, position and size, transitions, fades, nested sequences, overlapping clips) is listed in the status line, in the OTIO metadata and as EDL comments. Export only; no import. |

Each edit is one undo step; slipping takes the clip's linked sound along. No numeric trim entry. |
| F028 | Nested sequences and compound clips | Implemented (alpha) | Edit → "Nest selected clips" turns the selection into one clip on the lowest track it used, holding the clips as a sequence of their own (same canvas and frame rate, its own tracks). It is stored inside the project and rendered in the background to a ProRes cache file named after its content (previews show a note until then); it then trims, moves, speeds and takes effects like any video. Double-click (or Edit → Open nested sequence) edits it with its own undo history behind a bar leading back; going back is one undo step on the enclosing timeline. Nesting can go several levels deep; saving inside saves the whole project. "Take nested sequence apart" puts the clips back (from its start, at normal speed and without keyframes). Exports wait for the renders and are started from the main timeline. The rendered picture is opaque, so layers below a nested sequence are covered; Find in a folder does not look inside nested sequences. |
| F029 | Copy/paste clips and selected attributes | Implemented (alpha) | Copy (Ctrl+C) and paste at the playhead (Ctrl+V) within the session and across projects (the media comes along); the copy goes to its own track when free there, otherwise the nearest free track or a new one. Paste look (colour, effects, LUT) or paste all attributes (Ctrl+Alt+V: also transform, keyframes, shape, keying, volume, fades) onto the selected clip, in one undo step. No system-clipboard exchange or multi-clip selection. |
| F030 | Markers, in/out and timeline navigation | Implemented (alpha) | Markers (M) with name and colour, shown on the ruler and across the tracks; click to jump, double-click to rename or recolour, right-click to remove; previous/next marker (Ctrl+Left/Right). In and out points (I, O, Alt+X to clear) shown as a band on the ruler; the export dialog can export just the in/out range. Frame and edit navigation as before. Markers stay at timeline positions; they do not move with ripple edits. |
| F031 | Timeline zoom and frame-accurate seeking | Partial | Timeline zoom/fit; seeking renders only the playhead frame, so latency no longer grows with position (about 0.1 s for 1080p H.264 on a 4-core development container). Not qualified on the hardware profiles. |
| F032 | JKL shuttle and reverse audition | Partial | L plays forward and doubles to 2× and 4× on each press (FFmpeg real-time pacing at that speed, sound sped up with atempo, frames mapped by the faster clock); J scrubs backward at 1×, 2× and 4× (ten preview steps a second, stopping at the start); K pauses both; the transport shows the speed. Backward is a stepping preview without sound, not reverse playback. |
| F033 | Constant speed 0.1x to 100x | Implemented (alpha) | 0.1–100x with pitch kept (atempo chain); time-lapses up to 100x. Each output frame shows the source at exactly frame × speed, so fast clips agree in stills, playback and export. Very fast clips decode a lot of source per second, so playback of 50–100x clips may not keep up in real time. |
| F034 | Speed ramps and curve editor | Partial | "Speed ramp…" for video and sound clips: montage (fast, slow, fast), hero (a slow moment), bullet (a long slow moment), jump cut (slow, then fast), flash in (fast settling to normal) and flash out (speeding up). The clip and its linked sound are cut into up to 8 equal parts of the source, each at the clip's speed times the preset's curve there (0.1–100×, sound pitch kept); later clips on those tracks follow the new length; one undo step, and the parts stay editable. No continuous speed curve or curve editor. |
| F035 | Reverse and freeze frames | Partial | Reverse, and "Freeze frame here": the picture at the playhead becomes a still of 2 s with the clip's size, position and look; the clip and its detached audio are split there and the rest moves later. One undo step. Reversed clips freeze the frame they show. The hold length is set beside the button (0.1–60 s). No freeze of the whole composited frame. |
| F036 | Property keyframes and graph editor | Partial | Keyframes for scale, position, rotation, opacity and volume, with smooth (ease in/out) interpolation. Set at the playhead in the inspector, shown as timeline markers, kept attached through trim, split and speed changes. Each keyframe chooses how it moves on to the next: ease in and out, linear, ease in, ease out or hold, in the inspector when the playhead is on it. No graph editor or Bézier handles. |

| F039 | Crop, mirror and aspect ratios | Implemented (alpha) | Crop of all edges at once (keeps the aspect ratio) and of each edge on its own (left, right, top, bottom, up to 90 % per direction; the opposite edge gives way so a tenth stays), applied to the source before the picture is fitted, so a cropped picture keeps its shape; the AI matte is cropped the same way. | F067 | Loudness measurement and normalization | Partial | Export option: two-pass loudness normalisation.
