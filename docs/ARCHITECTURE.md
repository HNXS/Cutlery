# Architecture and decision record

## ADR 001 — a testable CPU reference backend for the first alpha

The design blueprint targets a native C++/Qt shell, shared render graph, D3D11 video processing and WASAPI audio. This alpha implements the shell and project/editing contract first and uses FFmpeg child processes as the **reference** backend. It does not claim the planned GPU/audio engine is complete.

`Project` stores media references and ordered clips. Timeline coordinates are integer frames at an exact rational frame rate. Source offsets and speed are rational values. Every editor mutation copies the project, validates the result, and commits it as one undo step. JSON schema 3 adds persistent track IDs and per-track snapping/magnetic modes to schema 2. Schema 1/2 migrate with snapping enabled and Magnet disabled, preserving existing clip positions. All schemas store timestamps as decimal strings to avoid floating-point integer loss. Unsupported schema versions are rejected without modifying the original file. QSaveFile performs atomic saves; one debounced recovery file is separate from the user's saved project.

`compileRender()` is shared by preview stills, live playback and export. It emits FFmpeg filter nodes and a separate argument list. Media paths are passed as process arguments, never a command shell or filter string. Titles become local transparent PNGs drawn with Qt's font shaping. No user title text is executed as a filter expression. Higher tracks composite last; same-track conflicts retain insertion order. Audio is resampled to 48 kHz stereo, adjusted, delayed, mixed and limited. Timeline length determines the output frame count.

`Editor` owns asynchronous ffprobe/FFmpeg jobs. An export compiles an immutable snapshot, writes a unique partial file in the destination folder, then renames it only on success. Existing destinations are refused. A failed/cancelled render removes its partial file. Preview jobs are debounced and replaced when seeking; revision/frame checks reject stale results. Playback is live (ADR 002); edits during playback restart it from the current frame.

`Project::move` inserts/reorders magnetic tracks at clip boundaries; `packTrack` keeps their order contiguous from frame zero. Trims retain source mapping while repacking the affected track. Free tracks retain arbitrary gaps and overlaps. Lock checks happen before edits; each operation including displaced neighbors is one undo transaction.

File drops queue asynchronous probes with stable destination track IDs. Each successful file imports and inserts atomically; the batch cursor advances after the last inserted clip. If the destination is removed/locked while probing, the file stays in the library with an explicit placement error. Other tracks are never silently substituted. A queue accepts at most 500 files; invalid files do not abort remaining imports. Internal library drags use Qt Quick Drag/DropArea; OS drops use URL MIME data.

`MediaAnalysis` streams 8 kHz mono PCM into a bounded peak accumulator (at most 6,001 bins per asset). Disk cache keys cover canonical path, size, modification time, duration and algorithm version. It processes one asset at a time with a 120-second timeout; assets over 24 hours have no waveform. Cache failures do not block editing. This is an overview, not a sample-accurate peak pyramid.

**Presenter overlays (schema 6).** Styled clips (rounded/circle shape, border or shadow) are scaled to their exact picture size (`Project::pictureSize`), so still layers can match it. The shape is an antialiased PNG mask. `blend` with `c3_mode=multiply` multiplies it into the picture's alpha, which keeps chroma-key transparency; `alphamerge` would replace it. Border ring and blurred drop shadow are drawn once into a larger PNG. That PNG holds only the ring, so keyed areas show the real background. The picture is overlaid onto it. Still layers are looped inputs retimed to the clip's frame timestamps. `boxblur` is GPL-only, so the shadow is blurred in C++. `colorkey` plus `despill` remove green/blue screens. The probe swaps width/height for ±90° display rotation, so portrait phone clips get correct shapes. In the viewer, `Editor::clipBounds` gives the clip rectangle at the playhead. Dragging commits position/size through `setClipValues` as one undo step, and keyframes the values when the property is animated.

**AI background removal (schema 7).** Inference runs in a separate worker, `cutlery-ai` (tasks `matte` and `upscale`), that links ONNX Runtime. The editor never loads the AI runtime, a model crash cannot take it down, and cancelling is a kill. CMake builds the worker only when `CUTLERY_ONNXRUNTIME_DIR` is set. Windows builds use the DirectML package. The worker opens each model with the DirectML provider on adapter 0 and falls back to the CPU provider if that fails, reporting `device gpu|cpu` to the editor. The worker reads frames from FFmpeg at 8 fps and the model's input size (U²-Net human segmentation, 320×320, ImageNet normalisation). It min-max normalises each matte, smooths it over time and resizes it to about 640 px at the picture's aspect. FFmpeg then stores the result as gray FFV1 with every frame a keyframe. `AiJobs` caches one result per task and media fingerprint (and size, for upscales) in `data/ai`, with a JSON sidecar giving the source range. It queues jobs and runs one at a time with progress and cancel. `Editor::aiSpan` processes only the range the clips using a task cover, plus a one-second margin. A new analysis keeps the range an earlier one covered. Clips store only `aiCutout`; the matte is local cache, not project data. `RenderOptions::mattes` passes available mattes to the compiler. For a cutout clip, the matte input seeks to the analysed frame at or before the picture's seek point. It is interpolated to the project rate (`framerate`), shifted by the remainder, and then sent through the same timing chain as the picture: speed, reverse, held ends and frame timestamps. It is cropped, sized and flipped like the picture, and `alphamerge` makes it the picture's alpha. Shape masks then multiply into that alpha. Tests use a generated matte to check the alignment (sub-frame seeks, offset ranges, flip and circle), and a one-node stand-in ONNX model (red channel as matte) to run the worker end to end. CI also runs the real model, including the deployed worker with only packaged DLLs, which shows the bundled `onnxruntime.dll` is used instead of the older copy Windows keeps in System32.

**AI upscale.** The `upscale` task decodes every frame of the range at the source rate (from ffprobe), at most 1080p. It runs Real-ESRGAN realesr-general-x4v3 (4×) on 384-pixel tiles with a 16-pixel margin of real neighbouring pixels, so memory stays bounded and seams do not show. FFmpeg resizes the result with Lanczos to the target: four times the source height, at most 2160p. It is stored as ProRes 422, intra-only, so seeks are exact. `RenderOptions::upscaled` swaps a clip's video input for that copy, seeking to the same source time minus the copy's start. Timing, effects and audio are unchanged. The published weights are PyTorch pickles; `tools/convert-realesrgan.py` reads them with a restricted unpickler and rebuilds the network node for node in ONNX (Conv, PRelu, DepthToSpace, Resize, Add), so CI needs neither PyTorch nor an unverified third-party ONNX export. Tests use stand-in ONNX models (red-channel matte, nearest-neighbour ×2) to run both tasks end to end.

**Automatic captions.** The `transcribe` task of `cutlery-ai` extracts a media range as 16 kHz mono PCM with FFmpeg. It runs `whisper-cli` on it as a separate process, from a static AVX2 build of a pinned whisper.cpp release, with Whisper large-v3-turbo q5_0, Silero VAD, 42-character lines and word-boundary splits. It turns the progress whisper prints into the shared progress protocol. The SRT result is cached by `AiJobs` per media fingerprint and language. Transcripts are per media file, not per timeline, so edits after a run only re-place captions. `Editor::generateCaptions` queues the media of every audible, forward-playing clip. When the last transcript arrives, `captionClips()` maps each cue through the clip's trim, position and speed. It drops cues mostly outside the trim and suppresses duplicates where the same speech plays on two tracks. The captions replace the clips of the "AI captions" track in one undo step. SRT import and the transcripts share `parseSrt()`. Tests use whisper.cpp's untrained test model for the full path; CI checks the real model on speech synthesized by Windows text-to-speech.

**Title templates (schema 10).** `Clip::titleStyle` selects a lower third with a plate, a lower third with an accent line, or a title card. `titlePlate()` draws the template tightly: the first text line is the name or heading, further lines are the role or subtitle, overlong lines are elided, and sizes follow the project height and the clip's scale. It also returns the plate's anchor: lower left inside the title-safe area, or the centre for cards. The renderer composites the plate image directly rather than a full-canvas title. Lower thirds slide in from the left over 0.45 s with a cubic ease-out in the overlay's x expression, and the clip's fades apply as alpha. The editor uses the same function for the preview frame, so the frame fits the plate exactly. Rotated or keyframed templates fall back to the plain title path.

**Blur and mosaic (schema 9).** An effect area is a clip without media or text (`Clip::effect` is "blur" or "pixelate"). Its size is `effectWidth × effectHeight` of the canvas times its scale, and `Project::pictureSize` reports that size, so the preview's drag and resize frame works unchanged. Clips composite in track order. On reaching an effect area, the compiler splits the picture composited so far, crops the rectangle, applies `gblur` or `pixelize` with the strength scaled to the output height (previews match exports), and overlays the result back. The overlay is enabled only during the clip's frames. Crop and overlay positions are per-frame expressions from the keyframe curves, so an area can follow a moving subject. Size is taken from the scale at the clip start, because crop sizes are fixed per stream. Effect areas never take part in transitions or SRT export. `Clip::blur` applies a Gaussian blur to a clip's own picture. `boxblur` would be simpler but is GPL-only.

**Timed captions (schema 8).** The transcribe task asks whisper-cli for one cue per word (`-ml 1 -sow`); transcripts use cache version 2. `groupWords()` builds lines: at most 42 characters, broken at pauses over 0.6 s and after sentence ends, with lone punctuation joined to the previous word. Each caption clip stores `wordStarts`, the clip-local frame of each word of its text. Trims shift them like keyframes, and a split divides the text and its starts between the halves. A styled caption ("karaoke" or "word") with matching timing renders from one sprite image: a band-high variant per word, stacked, with the word in `highlightColor`. A per-frame `crop` picks the variant with `y = band·Σ gte(t, start_i)` over clip-local time, so a caption costs one small looped input rather than one full-frame image per word. Rotation, scale and keyframes are not applied to sprite captions. Without matching timing (the text was edited to another word count) the caption renders as a plain title.

**Pauses and loudness.** `Editor::findPauses` runs FFmpeg's `silencedetect` on the selected clip's source range and converts the silent spans to clip-local frames, minus 0.12 s of padding on each side so words are not clipped. The result is tied to the project revision, so it goes stale after any edit. `Project::cutRanges` merges the ranges and cuts them from the end backwards: split after, split before, then a rippling remove. Earlier positions stay valid, and later clips on the track close up. `Project::linkedClips` finds detached audio (same media, start, range and speed on another track) so it is cut identically. Loudness normalisation is a measuring pass before export. The audio-only graph ends in `ebur128` instead of the limiter, `parseIntegratedLoudness` reads the summary, and the render applies one `volume` gain before an `alimiter` at 0.84 (about −1.5 dBFS). The gain is a single linear value, unlike FFmpeg's dynamic `loudnorm` mode, so the mix's dynamics stay as edited.

**Export profiles.** `ExportSettings` (format, quality, height) expands into ordered `Encoder` candidates (`encoderCandidates`). For H.264/HEVC these are NVENC, AMF, Quick Sync and Media Foundation; for AV1 the same hardware followed by SVT-AV1 software. VP9, ProRes and MPEG-4 are software-only. `EncoderResolver` proves each hardware candidate asynchronously by encoding five frames at the real size with the real arguments. A candidate that fails, for example because the GPU or driver is missing, is skipped and remembered for the session. The LGPL FFmpeg has no software H.264/HEVC encoder (x264/x265 are GPL), so those formats report a clear error when no hardware or Windows encoder works. Exports compile at the output size with `sws_flags=lanczos+accurate_rnd+full_chroma_int`, so a 4K export re-renders 4K sources at full detail instead of upscaling a composite.

**Keyframes (schema 5).** `Clip::keyframes` maps scale, x, y, rotation, opacity and volume to sorted `{frame, value, smooth}` lists in clip-local frames. `Clip::valueAt` interpolates linearly or with smoothstep easing, and the renderer emits the same function as an FFmpeg expression (`curve()`), so the inspector and output agree. Trim keeps keyframes at their timeline position, split rebases the second half, and speed changes rescale frames.

A clip with animated geometry is fitted to the canvas once. It is then rotated per frame inside a square that fits any angle (`rotate`, transparent fill) and resized per frame (`scale=eval=frame`). `overlay` positions the changing frame with per-frame `x`/`y` expressions. Each expression takes the clip-local frame from the stream time and a known offset. All of these are LGPL filters. `perspective` would be simpler, but it is GPL-only and missing from the shipped LGPL FFmpeg. `Get-FFmpeg.ps1` checks every filter the compiler emits. `rotate` always fills with transparent black: with `c=none`, uncovered corners are uninitialized, and a changing angle shows stale pixels there. Animated opacity sends one `colorchannelmixer` runtime command per run of equal values (`sendcmd`). Animated volume uses `volume=eval=frame` over clip-local audio time. Clips without keyframes use the original faster path.

**Transitions (schema 4).** A clip stores the transition *into* it from the clip that ends exactly at its start on the same track (`Project::previousAdjacent`). The effective length is limited by both clips, so neighbouring transitions never overlap. The transition is centred on the cut: the outgoing clip is extended past its end and the incoming clip before its start. Real source frames are used where the media has them; otherwise `tpad` holds the edge frame. Each clip's picture chain now renders an arbitrary range of clip-local frames. Timestamps are rebuilt from the frame counter (`settb` + `setpts=N+…`), so they stay frame-exact after padding. Clips joined by transitions are each placed on a transparent canvas and chained with FFmpeg `xfade`. For a partial window, compilation starts at the beginning of any transition the window starts inside, because `xfade` cannot begin mid-way; it then trims back. Tests check that windowed transition frames match the full render. Audio uses the same handles with equal-power (`qsin`) fades; handles beyond the source are silent. Video and audio now use separate inputs per clip because their handle ranges can differ.

`Thumbnails` builds one filmstrip per video/image asset in the background, one asset at a time, pausing during playback and export. FFmpeg decodes keyframes only (`-skip_frame nokey`). This is roughly 10× faster than full decoding: 1.2 s instead of 15 s for 3 minutes of 1080p H.264. It samples one tile per second, spreading tiles further apart for media over 200 s. All tiles are stored side by side in one JPEG, keyed by the same file fingerprint as waveforms. The layout is derived from the asset alone, so the cache needs no metadata. The timeline creates tile images only for the visible part of each clip, and it maps each tile through the clip's trim, speed and reverse. Thumbnails show the nearest keyframe at or before a position, so sources with sparse keyframes repeat tiles.

`KeyboardShortcuts` owns a validated registry and atomic per-user/portable preferences. QML disables timeline shortcuts during text entry and modal dialogs. 

`Main.qml` and `Timeline.qml` expose the implemented editing controls. Native file dialogs handle paths. Portable mode is selected only by an application-adjacent `portable.json`; its data folder must be writable. QLockFile prevents two instances from sharing the same recovery/cache folder.

## ADR 002 — windowed compilation and live playback (0.4)

0.3 had two costs that grew with the timeline. A still preview compiled the whole timeline and seeked the *output*, so FFmpeg decoded and composited everything from frame 0 to the playhead. Play first rendered the entire timeline to a cache file. On a 3-minute 1080p H.264 clip this meant roughly 12 s for a preview frame at 1:30, and roughly 40 s before playback could begin.

`RenderOptions` gives `compileRender()` a frame range. Only clips overlapping it are opened. Each input seeks directly to the first source time it needs, reversed clips included. Filters keep clip-local timestamps, so fades stay anchored to the clip, and the output starts at the window. A preview is a one-frame window: about 0.1 s regardless of position in the same test. Tests compare windowed frames against whole-timeline frames.

`Playback` runs two FFmpeg processes on a window from the playhead to the end. One writes raw yuv420p frames at viewer resolution to a pipe; the other writes 48 kHz PCM. `realtime`/`arealtime` filters pace both to wall-clock speed, which bounds memory without a disk cache. Audio goes to a `QAudioSink`, and its processed-sample count is the master clock. Video frames are pushed into the QML `VideoOutput`'s `QVideoSink` when the clock reaches them. If the CPU falls behind, late frames are skipped and sound continues. Without an audio device, the wall clock drives the picture. The first frame appeared after about 0.16 s in the same test. Preview stills are pushed into the same video sink, so pausing does not flash.

Two defects in the shared graph were found while proving window equivalence, and they affected export too. `setpts` truncates, so a clip placed at 1/3 s could start one frame early; placement is now rounded. Overlay enable windows now compare against half-frame boundaries instead of decimal-rounded frame edges. Clip sampling is biased by 1/8 frame, so exact half-frame ties (for example, 2× speed or 60 fps into 30 fps) resolve the same way wherever decoding starts.

## Known compromises

- Small projects only: whole-project snapshots (up to 60) and one decoder input per clip. No RAM budget, decoder pool or reverse-chunk strategy yet.
- PNG previews seek through a composed filtergraph. Scrubbing long timelines is not real-time.
- Preview resolution differs from export resolution; typography is rasterized at each target size. Composition semantics are shared, but pixel identity across resolutions is not promised.
- Source audio and video initially share a clip; detaching copies the audio timing to a new audio-only track and mutes the original clip. There is no pair resync yet. Edge trims preserve rational source offsets, including reverse; no roll/slip tools. Speed changes preserve source range, rounded down to full output frames.
- Crash recovery has one snapshot; no rolling journal or power-loss test qualification. A hard process kill may leave partial export/cache files. User originals are never edited.
- ffprobe runs in a child process but has no hostile-media sandbox. Network media paths are refused; FFmpeg and ffprobe input protocols are limited to file/pipe, including references inside local playlists. Media probing has a 30-second timeout. Inputs are not forensic evidence or security-isolated assets.
- H.264 Media Foundation is an optional explicit profile. Failure is surfaced; no hidden codec change or claim of certified compatibility.
- Live playback composites on the CPU in FFmpeg. Heavy multi-layer timelines drop frames rather than stall; the D3D11 engine remains the path to real-time heavy compositing. A reversed clip must decode its visible range before its first frame, so long reversed clips start slowly.
- Reversed clips can select an adjacent source frame in a preview window compared with export, because FFmpeg reassigns reversed timestamps from the decoded range. Forward clips match export.

## Next implementation gates

1. Windows clean-machine portable test, media corpus, large-project profiling, cache quota and render memory limits.
2. D3D11 renderer and audio clock using the same project contract; deterministic CPU/GPU frame comparisons.
3. Multilevel waveforms, proxies, a keyframe graph editor, advanced trims and linked-pair resync.
4. Colour management, broader codec qualification, installer and signed distribution.
5. Further local inference (word-level caption timing, eye contact, image upscaling, GPU speech recognition) on the worker/AI-pack pattern.
